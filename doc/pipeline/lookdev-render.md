# Lookdev ↔ Render — Houdini MaterialX / Karma

How shading and final rendering flow: **shaders are authored directly in Houdini MaterialX** (all shading
in-house, including complex procedural looks), final render is **Karma XPU**, and the hero lichen geometry
is **simmed in Houdini**. **Blender (Cycles) is the AD-side tool for mood / look-intent** — visual
direction, not production materials.

## The situation

- **Lichen geometry** is generated by the simulation system in **Houdini** — and it's **massive**
  (large-area coverage, hero density). See [../lichen/todo.md](../lichen/todo.md).
- **Shading** (materials, the look) is authored **directly in Houdini MaterialX** by the lead — including
  complex procedural shaders. Karma is MaterialX-native, so the look is built where it renders.
- **Final render** is in **Karma XPU** — Houdini/Solaris/USD-native, GPU+CPU hybrid.
- **Blender (Cycles)** is the AD-side tool for **mood / look-intent** — palette, lighting feel, the
  visual target. It sets the direction the Houdini shading matches; its materials are **never exported as
  production shaders**.
- **The tracked camera** (from the Nuke solve) imports into Solaris/LOPs, so camera + sim geo + render
  share one USD context — no cross-app transfer.

## Why there is no material gap

Materials are authored **where the geometry lives and where it renders** — Houdini MaterialX → Karma. There
is no Blender→MaterialX translation step, so the round-trip / fidelity problem that haunts a Blender-shading
pipeline simply doesn't arise here. Blender stays on the **mood / reference** side of the line; it is not in
the render path.

Any geometry modeled in Blender comes into Houdini as **USD** and is shaded in Houdini.

## Karma XPU notes (verify against the Houdini version in use)
- **MaterialX-native** → shading authored as MaterialX in Houdini renders directly, no translation.
- **GPU+CPU hybrid** → fast look iteration. **VRAM is the ceiling** for massive instanced lichen;
  instancing (not unique copies) is essential at coverage scale.
- **Feature parity:** XPU has historically lagged Karma CPU on some shader / AOV / volume features. The
  needed looks/AOVs must be confirmed XPU-supported before shading commits.
